# Telegram -> VK repost bot

Бот дублирует посты из Telegram в стену группы ВКонтакте: текст, эмодзи, фото (в том числе альбомы), видео, гифки и документы. Публичный, мультитенантный — каждый пользователь сам настраивает свои VK-группы и каналы через диалог с ботом, без правки конфигов на сервере.

## Как это работает

- **Новые посты канала:** добавь бота админом в Telegram-канал -> бот спросит (в личке, кнопками), в какую VK-группу репостить -> дальше каждый новый пост канала дублируется автоматически.
- **Старые/уже опубликованные посты:** обычный Bot API не даёт читать историю канала, поэтому вместо этого нужный пост просто пересылается ("Переслать") боту в личку — бот подхватывает форвард и постит его в VK.
- Если у пользователя больше одной VK-группы — при форварде или при добавлении бота в канал бот спрашивает кнопками, куда постить. Если группа одна — постит сразу без вопросов.
- Альбомы (несколько фото в одном посте/форварде) прилетают отдельными сообщениями с общим `media_group_id` — бот собирает их в течение `ALBUM_COLLECT_DELAY` секунд и публикует одним постом.
- Форматирование текста (жирный/курсив/ссылки) у ВК на стене не поддерживается — публикуется как обычный текст, эмодзи копируются как есть.
- Токены VK-групп и привязки каналов хранятся в JSON-файле на сервере (`STORAGE_PATH`, по умолчанию `data/storage.json`) — это чувствительные данные, файл в `.gitignore`, не коммитить.

## 1. Создать Telegram-бота

Написать [@BotFather](https://t.me/BotFather) -> `/newbot`, получить токен -> `TG_BOT_TOKEN`. Больше руками в Telegram настраивать ничего не нужно — каналы привязываются через сам бот (см. ниже).

## 2. Настроить .env

```bash
cp .env.example .env
# заполнить TG_BOT_TOKEN
```

VK-токены и id каналов сюда вписывать не нужно — их вводит каждый пользователь бота сам, через переписку с ботом.

## 3. Запуск локально (проверка)

```bash
python -m venv venv
venv/bin/pip install -r requirements.txt   # Windows: venv\Scripts\pip install -r requirements.txt
venv/bin/python -m bot.main                # Windows: venv\Scripts\python -m bot.main
```

Написать боту `/start`, добавить VK-группу (токен — не простой ключ доступа сообщества, а **токен пользователя-админа группы** с правами `wall,photos,video,docs,groups`; у бота есть команда `/vktoken` с пошаговой инструкцией, как его получить), переслать боту тестовый пост из любого канала — должен появиться на стене VK-группы.

## 4. Деплой на VPS через GitHub Actions

Гайд ниже — для работы под root (проще для одиночного VPS, без лишнего системного юзера).

### Первичный сетап VPS (один раз)

На чистом Ubuntu/Debian VPS, под root:

```bash
curl -fsSL https://raw.githubusercontent.com/SwathingSoap/tg2vk-bot/main/deploy/setup_vps.sh -o setup_vps.sh
bash setup_vps.sh https://github.com/SwathingSoap/tg2vk-bot.git
```

Скрипт: ставит python3/venv/git, клонирует репо в `/opt/telegram-vk-bot`, ставит венв и зависимости, копирует `deploy/telegram-vk-bot.service` в systemd. Сервис настраивается на запуск от того юзера, который вызвал скрипт (просто под root -> `root`, через `sudo` от другого юзера -> тот юзер).

После этого:

```bash
nano /opt/telegram-vk-bot/.env   # заполнить TG_BOT_TOKEN
systemctl start telegram-vk-bot
systemctl status telegram-vk-bot
journalctl -u telegram-vk-bot -f  # логи
```

### Секреты в GitHub

В репозитории: **Settings -> Secrets and variables -> Actions -> New repository secret**:

| Secret | Значение |
|---|---|
| `VPS_HOST` | IP или домен VPS |
| `VPS_USER` | `root` |
| `VPS_PASSWORD` | пароль root на VPS |
| `VPS_PORT` | обычно `22` |

### Как деплоится дальше

Любой `git push` в `main` триггерит `.github/workflows/deploy.yml`: заходит по SSH под root (по паролю), `git pull`, ставит зависимости, рестартует `systemctl restart telegram-vk-bot`. `.env` и `data/storage.json` на VPS руками не трогаются деплоем — только код.

## Ограничения

- Видео в VK после `video.save` обрабатывается асинхронно на стороне VK — сразу после публикации поста видео может показывать "обрабатывается" пару минут.
- Кастомные emoji (Premium Telegram) публикуются как их emoji-заглушка (обычный unicode), анимированная версия недоступна — ограничение самого VK.
- Редактирование/удаление поста в Telegram не синхронизируется с VK.
- Бот должен успеть написать пользователю в личку (после добавления в канал, после форварда с выбором группы) — для этого пользователь должен был хоть раз написать боту `/start`. Если бот не смог написать (нет личного диалога) — событие тихо теряется, в логах будет warning.
- Никакой изоляции на уровне доступа к чужим постам нет: если пользователь форварднул боту сообщение из чужого закрытого канала, бот всё равно попробует его обработать — доступ к контенту ограничен только тем, что видит сам Telegram-аккаунт пользователя при форварде.
